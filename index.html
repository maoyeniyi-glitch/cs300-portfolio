Case study: River Workshop

What was it?

I built a responsive landing page for River Workshop, a fictional community workshop. It introduces three practice sessions and gives visitors a clear way to explore them.

Who was it for?

The page was designed for beginners interested in HTML, CSS, and keyboard usability. It needed to remain readable on phones, tablets, and computers.

How did I make it?

I planned the header, introduction, session cards, About section, and footer. I built the content with HTML, styled it with CSS, and published it through GitHub Pages.

One decision and why

I used Grid for the session cards and Flexbox for the navigation. These let the cards and links change their arrangement as more screen space became available.

What did I check?

My assignment record documents checks at 375px, 768px, and 1280px, along with keyboard focus and horizontal scrolling. The recorded results showed stacked cards on phones and multiple columns on wider screens.

What would I improve?

I noticed an extra less-than symbol above the header on the published page. I would remove it and check the HTML for other markup errors.

Case study: JavaScript Data Toolkit

What was it?

I built a JavaScript console program that searches, filters, sorts, and summarizes book records. It helps users find books and see their total reading time.

Who was it for?

It was for people choosing books based on their interests and available reading time. I built it for CS300 and used Node.js to run the program in the console.

How did I make it?

I organized the code into separate functions for validation, normalization, filtering, searching, sorting, summaries, and reports. I used a verification harness to compare expected results with actual results.

One decision and why

I made a copy of the book array before sorting it. This allowed the program to return books in reading-time order without changing the original list.

What did I check?

My assignment record reports passing checks for empty lists, missing titles, invalid reading times, searches with different capitalization, and unchanged original data. Equal-value sorting was marked as not tested.

What would I improve?

Next, I would test books with the same reading time to check whether the title tie-breaker sorts them alphabetically. That would cover a gap in my existing test record.
